# OPR-INC-001 · Versión vulnerable de Next.js en despliegue Vercel

**Fecha:** 2026-11-13  
**Severidad:** P1 / crítica por riesgo de seguridad del framework  
**Estado:** corrección en código propuesta; **pendiente de CI y verificación de despliegue en Vercel**  
**Fuente:** registro de compilación aportado por el usuario.

## 1. Síntomas observados

- 13:56:14.599: inicio de compilación en Washington, D.C. (iad1).
- Máquina de 2 núcleos, 8 GB de RAM.
- Código: github.com/mejai84/oportunia, rama main, commit b84339d.
- Vercel CLI 65.14.0.
- Dependencias instaladas con Next.js 15.5.6.
- 13:56:40: compilación con advertencia CSS de autoprefixer.
- 13:56:46: generación de 10 páginas completada.
- 13:56:52: compilación finalizada en 37 segundos.
- 13:56:52.999: comienza "Deploying outputs...".
- 13:56:53.291: "Build cache cleared after a dependency security block. Redeploy to build with a clean cache."
- 13:56:53.291: "Vulnerable version of Next.js detected, please update immediately."

**Interpretación:** la construcción del artefacto terminó, pero el registro **no demuestra publicación final exitosa** y señala un bloqueo de seguridad de dependencias.

## 2. Causa raíz

El archivo package.json fijaba next=15.5.6, una versión anterior a los parches de la rama 15.5. La vulnerabilidad CVE-2025-66478 afectó a Next.js App Router y React Server Components, con posibilidad de ejecución remota de código en versiones no corregidas.

Referencias oficiales:
- https://nextjs.org/blog/CVE-2025-66478
- https://github.com/vercel/next.js/releases/tag/v15.5.29
- https://react.dev/blog/2025/12/11/denial-of-service-and-source-code-exposure-in-react-server-components

## 3. Corrección técnica

- Actualizar Next.js de 15.5.6 a **15.5.29**, publicada el 2026-11-03 con correcciones de seguridad adicionales.
- Actualizar react y react-dom de 19.1.1 a **19.1.5** para mantener una versión corregida en la rama 19.1.
- Sustituir align-items:start por align-items:flex-start en dos declaraciones CSS para resolver advertencia de compatibilidad.
- Añadir auditoría de dependencias de producción a GitHub Actions.
- Añadir documentación y criterios de aceptación posdespliegue.

No se modifica el esquema de datos ni la lógica de financiación.

## 4. Verificación requerida

- [ ] GitHub Actions aprueba auditoría, TypeScript, pruebas y build.
- [ ] Vercel recompila desde el commit corregido.
- [ ] No aparece la advertencia de versión vulnerable.
- [ ] El despliegue final aparece como Ready.
- [ ] Se valida URL HTTPS, rutas y simulador.
- [ ] Se confirma que el formulario sigue deshabilitado.
- [ ] Se registra la evidencia y se cierra la incidencia.

## 5. Riesgo residual y prevención

El repositorio no incluye package-lock.json: se debe incorporar para reproducibilidad y luego cambiar CI a npm ci. Debe mantenerse un proceso de revisión de alertas de dependencias y no promover cambios con vulnerabilidades altas o críticas.

**No hay evidencia en el log de explotación ni de fuga de datos.** Tampoco hay evidencia suficiente para declarar que el sitio estuvo expuesto públicamente. Si se comprueba que estuvo en línea usando una versión vulnerable, evaluar la rotación de secretos configurados y revisar logs de seguridad.

## 6. Observaciones secundarias

- npm advierte sobre cache-dir: configuración del entorno, no causa raíz.
- install-scripts de sharp/esbuild requieren evaluación; no se observa fallo de compilación por este motivo.
- La advertencia de autoprefixer no bloquea el build, pero se corrige por higiene de código.
